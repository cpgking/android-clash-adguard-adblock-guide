FlClash + AdGuardHomeForRoot 共存去广告方案
==================================================
记录时间：2026-10-19

一、问题现象
------------
FlClash 运行时：
  · 开启系统代理 → 外网正常，但其他 App 有广告；
  · 关闭系统代理 → 广告没了，但外网不通。

二、根本原因
------------
不是 AdGuard Home 坏了，也不是 FlClash 坏了，而是两者过滤的层次不同：

1. AdGuard Home 只能过滤 DNS 查询（UDP/TCP 53，重定向到 127.0.0.1:5591）。
   它看不到"已经交给代理转发的域名"。

2. FlClash 开启后：
   · VPN/TUN 的 DNS 是 172.19.0.2，FlClash 自己用 fake-ip + DoH 解析；
   · 系统代理模式下，App 直接把域名交给 127.0.0.1:7890；
   · 走代理的域名由代理节点在远端解析。
   这三种情况都不会经过 AdGuard Home，所以广告域名照常放行。

3. 关闭系统代理后，App 走系统 DNS，53 端口被 iptables 重定向到 AGH，
   广告域名返回 0.0.0.0 → 广告消失；但此时没有代理，外网自然不通。

结论：DNS 层过滤和代理层转发天然存在这个缺口。
      广告过滤必须放在 FlClash 的规则层做 REJECT。

三、解决方法（规则层拦截广告域名）
----------------------------------
1. 新建覆写脚本
   FlClash → 工具 → 进阶配置 → 脚本（覆写脚本） → 右上角"添加"，粘贴：

function main(config, profileName) {
  // 放在所有订阅规则最前面，命中即拒绝
  const adRules = [
    "GEOSITE,category-ads-all,REJECT",
  ];
  const oldRules = Array.isArray(config.rules) ? config.rules : [];
  config.rules = [...adRules, ...oldRules.filter(r => !adRules.includes(r))];
  return config;
}

   保存脚本。

2. 把脚本挂到订阅上
   配置 → 订阅卡片右边三个点 → 更多 → 覆写 → 覆写模式选"脚本"
   → 选中刚才的脚本 → 保存 → 彻底杀掉 FlClash 后台再重新打开
   → 启动连接。

3. 系统代理 / TUN 的选择
   · 推荐只用"虚拟网卡 / TUN"模式，系统代理可以关闭；
     TUN 已经全量接管流量，系统代理只是额外给"认代理的 App"用。
   · 如果只用系统代理模式，不认系统代理的 App 本来就没法访问外网，
     这是系统代理的覆盖面问题，不是故障。

4.（可选）让 FlClash 的 DNS 也走 AdGuard Home
   工具 → 进阶配置 → DNS，界面字段对应关系如下：

     「域名服务器」（副标题：用于解析域名）
         ← 这就是 Nameservers / nameserver
         ← 要接 AGH 就填：127.0.0.1:5591

     「默认域名服务器」（副标题：用于解析DNS服务器）
         ← default-nameserver，只用来引导解析 DoH/DoT 服务器本身的域名
         ← 必须填"纯 IP 的 DNS"（可带端口），不能填 DoH/DoT 网址或域名
         ← 推荐填：
              223.5.5.5
              119.29.29.29
              114.114.114.114
         ← 也可以保留 AGH 并加公共 DNS 兜底：
              127.0.0.1:5591
              223.5.5.5
              119.29.29.29
         ← 当前值 127.0.0.1:5591 是可用的；它只负责引导解析，
           不是广告过滤入口，也不是 Nameservers
         ← 注意：它不是 Nameservers，不要填错到这里

     「代理域名服务器」（副标题：用于解析代理节点的域名）
         ← proxy-server-nameserver
         ← 保持原来的 DoH，或填 223.5.5.5

   操作：点「域名服务器」→ 添加 127.0.0.1:5591 → 保存。

   注意：
   · 必须确保「覆写 DNS」开关是打开的（当前 overrideDns=true），
     只改字段不打开开关是无效的；
   · fake-ip 模式下它主要影响 DIRECT 直连的解析，
     不能替代第 1 步的规则层拦截；
   · 如果「域名服务器」只填 AGH，AGH 挂掉时 FlClash 的 DNS 也会挂，
     不想有单点依赖就再保留一个 DoH 作为备选。

四、实测结果（2026-10-19 实测）
----------------------------------
最终生效配置（复核通过）：
  overrideDns = true
  域名服务器       = 127.0.0.1:5591
  默认域名服务器   = 114.114.114.114 / 119.29.29.29 / 223.5.5.5
  代理域名服务器   = https://doh.pub/dns-query
  DNS 模式         = fake-ip
  规则第一条       = GEOSITE,category-ads-all,REJECT

可选加强（不是必须）：
  · nameserver-policy 里的 geosite:cn → https://doh.pub/dns-query
    会让国内域名绕过 AGH；
  · fallback（tls://8.8.4.4、tls://1.1.1.1）也可能让部分境外域名绕过 AGH。
  广告目前由规则层拦截，不受影响；若想让 AGH 接管更多解析，可清空这两项。

1. FlClash 运行时配置已生效：
   /data/data/com.follow.clash/files/config.yaml 第 740 行：
     - "GEOSITE,category-ads-all,REJECT"
   该规则位于 rules 列表第一条，优先于订阅自带规则。

2. 走 FlClash 代理（127.0.0.1:7890）测试：
   https://www.google.com/generate_204   → 204（正常）
   https://www.baidu.com                 → 200（正常）
   https://pagead2.googlesyndication.com → 000，约 0.02 秒失败（REJECT）
   https://doubleclick.net               → 000，约 0.02 秒失败（REJECT）
   https://www.google-analytics.com      → 000（REJECT）
   https://app-measurement.com           → 000（REJECT）
   https://gdt.qq.com                    → 000（REJECT）
   https://mi.gdt.qq.com                 → 000（REJECT）
   https://github.com                    → 200（正常）

3. 直连（TUN）测试：
   google / baidu 正常；pagead2、doubleclick 均被拦截。

4. AdGuard Home 仍正常：
   doubleclick.net → 0.0.0.0
   www.baidu.com   → 正常解析

五、注意事项
------------
· 规则只能拦"域名级"广告；App 内嵌原生广告、与正文同域名的广告
  拦不住，这是 DNS/域名规则的共同限制。
· 个别漏网的广告域名，可以在脚本 adRules 里显式添加，例如：
    "DOMAIN-SUFFIX,gdt.qq.com,REJECT",
    "DOMAIN-SUFFIX,pangolin-sdk-toutiao.com,REJECT",
    "DOMAIN-SUFFIX,umeng.com,REJECT",
· 如果某些 App 直接连 IP、不走域名，可以打开 FlClash 的
  "嗅探 / Sniffer"，让规则能按 TLS SNI 识别域名。
· 若误拦了正常 App，删除或注释对应的规则即可。

六、回滚方法
------------
· 配置 → 订阅三个点 → 更多 → 覆写 → 关闭覆写，或删除脚本；
· 或删除规则 "GEOSITE,category-ads-all,REJECT"；
· 重启 FlClash 后恢复原状。

七、关键路径速查
----------------
· AdGuard Home DNS：127.0.0.1:5591
· AdGuard Home 面板：http://127.0.0.1:3000
· FlClash 运行配置：/data/data/com.follow.clash/files/config.yaml
· FlClash 代理端口：127.0.0.1:7890
· FlClash VPN DNS：172.19.0.2
· FlClash DNS 字段对照：
    「域名服务器」       = nameserver（解析目标域名，接 AGH 填这里）
    「默认域名服务器」   = default-nameserver（解析 DNS 服务器地址）
    「代理域名服务器」   = proxy-server-nameserver（解析代理节点域名）
· 默认域名服务器只能填纯 IP（可带端口），不能填 DoH/DoT 网址或域名
· 规则校验命令：
  su -c 'grep -n "category-ads-all" /data/data/com.follow.clash/files/config.yaml'

八、Clash Meta for Android（com.github.metacubex.clash.meta）同样处理
------------------------------------------------------------------
版本：2.11.34.Meta
原理完全一样：AGH 的 DNS 过滤被代理绕过。首选规则层 REJECT；
不想改 URL 配置时，可用 DNS 覆写 + redir-host 作为替代。

注意：CMFA 与 FlClash 不能同时开——
  · 两者都要占用 VPN（同一时间只能有一个 VpnService）；
  · 两者 mixed-port 都是 7890。
  测试 CMFA 前先停止 FlClash（停止连接并杀掉后台），AGH 不用动。

1. 为什么看不到 rules
   当前订阅是 URL 类型。CMFA 2.11.34 对 URL 类型的配置是只读的
   （FilesActivity 里 configurationEditable = (type != Url)）：
     · 配置 → "⋮" → 编辑，只能改名称/URL/自动更新，没有 rules；
     · rules 在 config.yaml 里，入口是：编辑 → 浏览文件 → config.yaml，
       但 URL 类型只能看、不能改。

2. 推荐：复制成 File 配置后再加规则
   配置 → 你的订阅右侧"⋮" → 复制
   → CMFA 会生成一个 File 类型的本地副本（可直接编辑）
   → 自动进入"参数"页 → 点「浏览文件」
   → 打开 config.yaml
   → 在 rules: 下第一行插入（缩进与原文件一致，通常是 4 个空格）：
        - 'GEOSITE,category-ads-all,REJECT'
   → 保存并返回 → 激活这个副本 → 启动。
   CMFA 的 geosite.dat 已包含 CATEGORY-ADS-ALL，可直接用。

   如果点 config.yaml 没有可用的文本编辑器：
     · 在文件列表里对 config.yaml 选"导出"，存到下载目录；
     · 用 Termux 或 MT 管理器编辑后，再用"导入"覆盖回去；
     · 或者复制完成后告诉我，我用 root 直接改这个本地副本。

   注意：File 类型副本不会自动更新。原 URL 订阅更新后，
   需要重新复制/重新加规则。

3. 备选：不改规则，用 DNS 覆写让 AGH 拦广告
   设置 → 覆写 → DNS：
     增强模式：redir-host
     Name Server：127.0.0.1:5591
     Default Name Server：114.114.114.114、119.29.29.29、223.5.5.5
     Fallback Name Server：清空或保留
   这样 CMFA 会把域名交给 AGH 解析，广告域名返回 0.0.0.0 直接失败。
   优点：URL 订阅不用改，订阅更新不影响；覆写保存在 override.json。
   缺点：只拦 DNS 层；App 自带 DoH/DoT 或直接走 HTTP 代理的流量会绕过；
         redir-host 兼容性不如 fake-ip。

   如果已经做了第 2 步的规则，这一步可改成：
     增强模式保持 fake-ip，Name Server 填 127.0.0.1:5591。

4. 验证
   规则是否注入：
     su -c 'grep -n "category-ads-all" /data/data/com.github.metacubex.clash.meta/files/processing/config.yaml'
   启动 CMFA 后测试（应快速返回 000）：
     curl -x http://127.0.0.1:7890 -o /dev/null -w '%{http_code}\n' https://pagead2.googlesyndication.com/
   正常站点应仍可用：
     curl -x http://127.0.0.1:7890 -o /dev/null -w '%{http_code}\n' https://www.google.com/generate_204
